# Design records and assets

Follow the workspace source map. By default, brand/discovery.md records interview answers and concept choices; brand/identity.md records selected visual rules and links to asset files. Store actual reusable text/visual outputs in assets/drafts/ and promote an exact approved revision to assets/staged/. This does not establish that it has been published. Reuse shared masters and content across surfaces.

## Version handling
Preserve existing versions; create a new revision for meaningful changes. Record selections by exact ID, for example B/v2. Promote/link into assets/staged/ only after approval, with provenance back to that version. If final files are not approved yet, leave them under their option and mark brand/identity.md as pending. Before replacing an approved version, retain it in the existing version history or archive it and update the guide explicitly.

## Assets
Omit unused directories: no symbol for a wordmark-only identity, no banners unless needed. Keep banners platform agnostic; optional size/crop exports derive from the generic master. Record relative paths, purpose, variant, format and pixel dimensions (SVG viewBox/aspect ratio for vector masters). Include editable sources where useful; document font fallbacks and source/licence links. Verify saved files exist; descriptions are not substitutes for assets.
