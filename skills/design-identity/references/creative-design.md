## Select rather than stack
- Load only the resource needed for the current stage. Resolve conflicting defaults against the user's approved brief; do not run competing end-to-end design workflows simultaneously.
- Keep personal-brand responsible for positioning and brand-kit inventory; keep design-identity responsible for visual development and production handoff. Let audit skills check observable implementations against approved references.
- In a host with skill support, use an installed skill only when available. Otherwise consult its accessible documentation as reference; do not claim reading a GitHub page installed or executed it.
- Preserve existing tool instructions and permissions. Do not execute upstream scripts merely because a document recommends them.
- Link to upstream work. Before copying instructions, scripts, fonts or assets, check the specific licence and preserve required attribution. No third-party code or asset collection is vendored here.
- Recheck upstream paths and requirements when using them; this index is not a version-pinned dependency lockfile.

## Deliverable and acceptance contract
For a selected identity, agree the applicable set: full-name lockup, compact mark, favicon, light/dark and one-colour variants, typography, palette, editable masters and concise usage rules. Do not force an unnecessary symbol or variant on every brief.

Evaluate distinctiveness with bounded comparison, name readability, small-size performance, monochrome and reversed rendering, scalability, optical craft and coherence across applications. Avoid generic results by testing concrete forms against relevant references, not by declaring a design unique.

Keep approved core geometry intact across applications while allowing documented crops, layouts, colours and font substitutions. Compare actual website, GitHub, LinkedIn and résumé evidence where accessible; report access limits instead of inferring visual compliance.
